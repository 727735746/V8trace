# 产物绑定与独立工作区

这些是构建机上的本地工具；运行软件仍只需要随包 C++ 内核与 Windows UI，不增加 Python / Node 运行时回退。工具不签名、不发布、不迁移正在使用的 Chromium checkout，也不改分页文件或关闭其他程序。

## 版本与绑定

`packageBatchId` 是一次组装的独立批次，不等于 UI 文件版本、C++ 内核版本或 Chromium / V8 revision。`package-manifest.json` 继续保留原字段，并新增输入摘要和外置绑定文件名；批次只在新目录生成。

`build-cpp.ps1` / `verify-runtime.ps1` 在构建前记录源文件，配置后固定依赖源与编译器；编译、测试、UI 组装后重新核对。已有共享依赖在配置前也先固定，后续变化会中止此尝试。依赖的“只读”指消费约定和前后全量字节复核，不伪称已设置只读卷或 ACL。若生成器需要改依赖源，请使用独立副本及新的容量计划，不以可写硬链接共享。

主机输出持有禁止重解析/重命名的目录句柄和独占 `.v8trace-host.lock`，同一输出上再启动构建会失败。来源变化后保留本次缓存 / 新候选及回执，不把旧测试结果挪到新二进制。CTest JUnit 必须实际包含用例，且失败、禁用和跳过均为零。

外置 `PACKAGE.binding.json` 绑定：

- UI 输入、UI 文件及实际 C# 编译器文件；
- C++ 输入、运行身份、运行文件、源/依赖快照与实际 JUnit 回执；
- 浏览器核心文件、描述文件和完整运行清单，以及各运行文件字节；
- 包清单、全部包文件和批次号。

绑定放在包外，避免把“自身哈希”写进包后形成循环。原始测试回执与源码输入清单留在内部构建证据目录，不把专业源码或调试日志塞进软件包。当前源码复核用 `--source`；历史字节核对不要求源目录或旧缓存仍处于原分支，但内部的原始输入清单 / 测试回执仍须保留并满足原哈希。

```powershell
.\build-cpp.ps1 -Edition community -BuildRoot G:\v8-trace-build\host\community -OutputPath F:\packages\Community-BATCH -PackageBatchId community-BATCH -Jobs 1
python -B .\editions\artifact_binding.py check --binding F:\packages\Community-BATCH.binding.json --source .
python -B .\editions\verify-host-package.py --package F:\packages\Community-BATCH --edition community --output F:\evidence\host-check.json
.\editions\verify-distribution.ps1 -PackagePath F:\packages\Community-BATCH -RequireBinding
```

普通文件完整性检查输出 `FILES_ONLY_PENDING_BINDING`；带精确绑定后输出 `FILES_AND_BINDING_PASS`。二者都不是网站、原生/媒体或整包发行成功。旧 host 清单标为 `legacy-host-files-verified-unbound`，不静默补成新绑定。

## 验收与 ZIP

实际验收报告使用 `v8trace/product-acceptance/1` 信封，携带目标绑定文件 SHA-256、批次、版本、UI / runtime SHA、范围、实际门槛报告的路径/长度/SHA。门槛报告本身必须通过，并包含与目标一致的组件哈希观察；`native-media` 还要求原生核心/描述/运行清单身份、实际浏览器运行和媒体验证。旧报告或另一个包的报告拒绝混用。

`acceptance` 仅绑定已观察到的报告，不替代执行测试，也不自动晋升或远端发布。`archive` 流式读取 ZIP 的全部文件，拒绝路径穿越、重复/别名、链接、缺失或额外文件，核对解压字节和整个 ZIP SHA；不把 ZIP 解压到用户目录。若 ZIP 显式包含顶层目录，用 `--archive-prefix TOP`，不猜前缀。

```text
python -B editions/artifact_binding.py acceptance --binding PRODUCT.binding.json --report ACTUAL-ACCEPTANCE.json --output ACCEPTANCE.bound.json
python -B editions/artifact_binding.py archive --binding PRODUCT.binding.json --archive PRODUCT.zip --acceptance ACCEPTANCE.bound.json --output ARCHIVE.bound.json
python -B editions/artifact_binding.py check-archive --report ARCHIVE.bound.json
```

文件/绑定回执是字节及关联检查，不是第三方签名或独立测试执行证明；`wholePackageReleaseEligible` 不由这些工具自动改为 true。最终发行仍需当前队列的双版本实际原生、UI、媒体及完整软件门槛。

## 工作区规划与准备

默认只生成只读计划。先对八个依赖源生成固定清单；新 root 的空间要求由操作者提供，工具按同一卷合计，不把每项单独拿同一份空闲容量重复计算。它读取当前可用物理内存、可用提交量和磁盘空间，不预留空间，也不保证以后其他程序不会消耗资源。

```json
{
  "protocol": "v8trace/workspace-request/1",
  "jobs": 1,
  "copyMode": "independent",
  "dependencies": {"path": "DEPENDENCY_INPUTS.json", "bytes": 123, "sha256": "PINNED_SHA256"},
  "protectedRoots": ["G:/v8-trace-build/src", "F:/packages/ROLLBACK"],
  "roots": [
    {"path": "G:/v8ws/community", "role": "native-build", "edition": "community", "requiredBytes": 268435456000},
    {"path": "G:/v8ws/professional", "role": "native-build", "edition": "professional", "requiredBytes": 268435456000}
  ]
}
```

上述空间只是请求示例，不是当前 checkout 的测量值。计划支持 checkout / native-build / host-build / package；host-build 必须给出实际 `source`。父目录需明确准备，`prepare` 只创建新空 root 和各自标记，不复制源码、依赖、用户日志或既有产物。

```text
python -B editions/artifact_binding.py dependencies --build EXISTING_HOST --output DEPENDENCY_INPUTS.json
python -B editions/workspace_plan.py plan --request REQUEST.json --output PLAN.json
python -B editions/workspace_plan.py prepare --plan PLAN.json --output PREPARED.json
```

准备前再次核对容量、源 pin、活动所有者、目录身份和计划哈希。别名、重解析路径、根重叠、混用版本/角色、未知已有目录、可写文件多硬链接、现有采集/日志/软件目录均拒绝。活动 Ninja/CMake/CTest 按真实命令和父进程归属观察；归属不明则保留所有者，不另起构建。识别到 GN checkout 时连同其源根保护。当前 Windows 写入后端持有 no-reparse 目录句柄；不提供其他平台的空 root 准备保证。

为避免把未核验的长路径能力当成可用，checkout / native-build root 采用 80 个 UTF-16 单元、host-build / package root 采用 160 个的保守入口预算；不改注册表长路径设置。默认内存/提交预算随 1–4 个 job 增加，可在显式计划里给出资源需求。所有观察均为当时值，不是容量预留。

`-WorkspacePlan PLAN.json` 可交给两个现有主机消费者使用，实际 root / edition 必须已经由该计划准备。未提供计划时，单主机消费者仍先做资源、路径、所有者及现有缓存 source/edition 检查，再创建或使用显式选择的主机 root；不迁移活动的双版本原生树。失败保留已创建的独立空目录，重新选择/核对，不递归回收用户路径。

## 回归

`test_artifact_binding.py` 注入变化的源码、UI、runtime、原生核心、描述/清单、回执、ZIP 以及错误关联；`test_workspace_plan.py` 覆盖卷容量合计、内存/提交、活动/未知所有者、别名、混版和硬链接。测试只创建带固定前缀的独立临时夹具，不是浏览器运行或完整软件验收。
