# 发行阶段与事务导出

`export-community-host.py` 与 `export-community.py` 保留原 CLI 参数。目标需为源码树外的新目录。文件先写入目标父目录下的 `.目标名.export-*` 暂存，完成来源边界检查、正文凭据形状检查和完整文件清单/长度/SHA-256 校验后，才以排他的目录重命名提交。现有目标和竞态创建的目标均保留；没有自动覆盖或递归清理。复制、清单或提交失败时最终目录保持未提交，暂存和 `FAILURE.json` 留作检查。若其他进程抢先创建目标，保留它而非删除。

Windows 使用不覆盖目标的 `os.rename`，对共享冲突作有限重试；Linux 使用 `renameat2(RENAME_NOREPLACE)`，其他未实现的平台明确停止。语义依据 [Python 文件重命名文档](https://docs.python.org/3/library/os.html#os.rename) 与 [Linux man-pages](https://man7.org/linux/man-pages/man2/rename.2.html)。不以检查目标后再允许覆盖的重命名模拟排他提交。PS1 原始 BOM/字节默认复制；既有明确变换继续使用其原先编码策略。

`release_state.py` 只记录本地阶段观察，不运行构建、验证、打包或远端发布。build / observer / validation / package / publication 使用各自状态；每份回执带独立 attempt、实际文件绑定和父回执哈希，追加而非重写历史。阶段文件写完并刷新后才以排他文件链接提交；失败临时文件保留。

两版监督器保留 `v8trace/build-supervisor/1` 和现有调用参数，新增 `phases`、监督进程与子进程的出生标识/完整命令/可执行路径。观察器写入失败不再只剩一个含混的失败标记；旧顶层状态继续兼容原控制器。短命子进程可能在身份查询前已结束，此时不伪造出生身份。

新增可选 `run_build(..., resume_state=旧回执)`：在独占输出锁内核对原 checkout、output、完整 command 和全部源输入指纹，再检查原监督/子进程身份。活动所有者、PID 复用、命令或输入变化均停止新的 Ninja；对缺少出生身份的旧回执，活动 PID 仍保留待查。不自动认领活动子进程或改动社区源码投影。现有运行中的私有恢复流程继续持有原锁；本轮没有切换它的执行代码或更改活动 Chromium 源码。

这不是完整发行验收。编译、原生运行、采集期媒体、最终目录与 ZIP 仍须分别有配套真实回执；publication 不会因 package 状态改变而自动变为已发布。

测试入口：`python -B editions/test_atomic_export.py`、`python -B editions/test_release_state.py`，以及原 `runtime-cpp/tests/build_supervisor_test.py`。导出测试还实际运行导出源码中的测试驱动；Windows 覆盖真实目录共享占用。原始失败和暂存不会自动转为成功。
