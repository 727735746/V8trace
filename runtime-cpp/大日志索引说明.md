# 大日志关联与导出

## 实现边界

关联、案例导出使用 C++ 静态链接 SQLite 的磁盘索引，不调用 Python 或 Node。固定 SQLite 3.54.1 的官方源码及 SHA-256，下载时另与官方 SHA3-256 核对，依据见本轮 artifacts/sqlite-source.json；许可证随软件交付。

调用结构、活动调用、Hook span、源码身份、资源及环境依赖放到磁盘；资源请求按生产者作用域与 request ID 查询，不再逐请求遍历全部资源。同步包围使用 R-tree 候选索引，再用原始 JSON 数值进行严格开区间比较；float32 候选采用包含边界，避免 64 位时间戳精度丢失导致漏选。候选关联仍不是异步因果关系。

`scripts.json`、静态资源、冲突、缺项和环境依赖采用流式输出；同 URL 的大量冲突也逐项写入，不聚合整个冲突组进内存。正文仍为内容寻址文件；复制后再次校验实际大小和 SHA-256。

## 缓存、磁盘和错误

- 配置 8 MiB SQLite 页缓存、文件型临时排序，关闭 mmap；这不是进程 RSS 硬上限。单条记录、SQL 工作内存、文件流和宿主写队列仍占内存。
- `diskIndex` 记录实际页缓存、查询/读行/全扫描步数、最大读行、数据库大小及单值上限。超限或 I/O 错误明确失败，不裁剪内容，也不伪造完整索引。
- 临时索引在 `analysis-cpp-UUID` 目录，正常及异常结束关闭句柄并仅清理所属目录。关联工作区位于采集包，导出工作区位于目标父目录，不要求改写只读源包。
- 捕获原始值、正文、源码、gap 与关联语义不由索引重新定义；旧包继续支持。磁盘需求包含索引、排序及新导出包，开始前预留空间。

## 验证入口

`v8trace-index-tests` 对照测试专用旧实现检查调用、来源、Hook、资源关联和导出等价；覆盖重名、生成器分段、异常、开放调用、64 位严格边界、孤立代理项、NUL、嵌套流式 JSON 和异常清理。

```powershell
# C++ 构建目录内
.\v8trace-index-tests.exe
.\v8trace-index-tests.exe --scale 100000
```

规模模式记录生成、关联、导出耗时与实际进程峰值，不把页缓存大小当作峰值；测量结果以 artifacts 下本轮真实输出为准。

依据：[SQLite R-tree](https://www.sqlite.org/rtree.html)、[SQLite PRAGMA](https://www.sqlite.org/pragma.html)、[源码下载](https://www.sqlite.org/download.html)。
