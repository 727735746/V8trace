# 无损分块、持续搬运与恢复

UTF-8 中文。`chunkSpool` 开启持久分块，`streamTCP` 额外开启边产生边搬运。UI 位于「TCP 日志传输」，地址/端口/令牌与现有 TCP 页面共用。默认保持旧采集目录，分块目录为同级 `capture-xxx.stream`，两者都保留。

## 语义与性能

- 分块协议 `v8trace/chunk/1`，1 MiB 原始字节上限；完整 zstd 压缩，逐块保留序号、文件路径/偏移、原始/编码长度及 SHA-256。跨块 UTF-8、UTF-16、NUL 和二进制都按字节重建。
- 小日志先合并，最多 16 个目标、8 MiB 待封块内存；开启网络时约每秒封出余量，写盘/调度背压会延长时点。不是每条调用单独 fsync。
- 只有已封块的不可变目录进入 TCP；每块单独复用 TCP/1 的持久 ACK、校验、重试/断线续传。网络故障保留磁盘 spool，不把数据塞进无限内存队列。
- 这是**宿主已产生日志的持续搬运**。定制浏览器的原始 trace 可能在停止/刷出后才可归档，未实现 V8 生产线程直连 TCP。暂停不补录。TCP 是明文，跨机器需令牌与可信链路或加密隧道。
- 已完成刷出的原生 trace / NetLog 在支持的文件系统上与内容 blob 使用硬链接，避免同一原始大 JSON 在采集目录物理复制两份；失败时退回完整复制。临时重组文件不使用此机制。

## 三种状态分开

1. `spool.json` 中 `sealedChunks`：本地已经持久封块的数量。强杀可能留下 `.new`，它不算已封块。
2. `acknowledgedChunks`：接收端确认的块数；历史 ACK 可通过幂等重发恢复。只收到块不代表最终采集包完整。
3. `commit/stream-commit.json` 与 `files.jsonl`：所有最终文件的长度/SHA-256清单。收到独立最终提交后，`remoteCommitted` 才为 true。该提交证明归档结构，不承诺网页采集没有缺口；仍需看 `summary.json` / `gaps.jsonl`。

停止时默认最多等待网络排空 5 秒，再保留待传项；底层 socket 的当前超时退出可能额外花费约 15 秒。`streamDrainTimeout` 可设 0–120000 毫秒，`streamSpoolMaxBytes` 默认 1 TiB 编码数据预算。磁盘不足或本地封块失败会有错误，原始目录与已封块保持不变。传输状态文件不递归包含自身。

## 命令

```powershell
# 已有采集包压缩分块，源目录不删除
.\runtime\v8trace-runtime.exe stream-pack --capture .\logs\capture-X --spool .\logs\capture-X.stream
# 接收端常驻，不加 --once（一次采集会有多个独立分块事务）
.\runtime\v8trace-runtime.exe receive --root .\received --bind 127.0.0.1 --port 17880
# 离线/中断后的续传；已确认不可变块幂等复用
.\runtime\v8trace-runtime.exe stream-send --spool .\logs\capture-X.stream --host 127.0.0.1 --port 17880
# 本地 spool 或接收端汇总目录重建到新目录
.\runtime\v8trace-runtime.exe stream-unpack --spool .\received --output .\restored --stream-id STREAM_ID
# 只解码一个块，不载入全日志
.\runtime\v8trace-runtime.exe stream-decode --chunk .\logs\capture-X.stream\chunks\00000000000000000001 --output .\chunk.raw
```

重建先检查最终提交和清单，再使用磁盘索引逐文件/逐块检查，完整通过后才提交目标目录。缺块、错序、重复位置、校验错误、未提交流都明确报错并保留源；失败只清理本次拥有的 `stream-restore-*` 临时目录。接收端 `.incoming` 和本地 `.new` 不当成已提交对象。
