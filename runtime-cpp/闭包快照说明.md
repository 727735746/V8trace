# 定向闭包绑定快照

UI“调用过滤”页的“定向闭包绑定快照”默认关闭。启用需逐次 JSCall 和具体的脚本/函数白名单，空范围及仅 `*`/`?` 的规则会报错。目标范围沿用 JSCall 生产端过滤，不影响 HTTP、Opcode 等通道。闭包与 `jsCallValues` 独立：参数结构模式也可显式采集闭包值。

CLI 配置项为 `closureBindings`。`closureScopes` 默认 32，`closureBindingsLimit` 默认 4096；值图 `closureDepth=2`、`closureNodes=256`、`closureProperties=4096`。这些是明确的观察预算，不是采样或按函数次数丢弃。到达边界会在原记录和 `gaps.jsonl` 中保留说明。

在原生 V8 所属线程按当前调用阶段，读取函数捕获的 Context 词法链，包括名称、槽位、声明模式、位置及当前值；ContextCell 的 tagged/int32/float64 值按真实存储状态读取，保留 float64 位模式。对象采用只读原始存储值图，不额外执行访问器或 Proxy，不跨调用缓存可变对象。

`valueGraphScope=whole-closure-snapshot` 表示一个快照内所有绑定共用节点编号，可以表达跨绑定别名和循环。不要把 `refNodeId` 当作跨调用稳定对象 ID；地址和 GC 世代也只代表观察时状态。

它不是“全部局部变量”：当前函数的栈局部、消除的绑定、模块 live binding、with/eval 动态解析不被凭空物化。相关边界明确保留；未初始化的 hole 不等于 undefined。异常路径优先在原生抛出观察点、栈帧展开之前保存词法真值，标注 `throw-observation-before-unwind`；未观察到该点的已展开栈帧保留边界，不编造值。generator 仍是已有的激活段入口/挂起/恢复策略，非不存在的连续栈帧。

快照在 `events/jscall.jsonl` 的 payload.closure 中，汇总为 `closure-summary.json`，导出时一并携带。新后端必须声明 `v8trace/closure/1` 与匹配补丁身份；旧浏览器在启动前报版本不匹配。语法/协议验证和实际 Chromium 运行验证分开记录，最终发行仍要求新内核回归。
