一、当前候选与构建条件
  F:\project\chrome_envs\v8-trace\dist\V8Trace-HTTPRoot-Candidate-20261027-R7\V8Trace.exe
  同目录 chromium\chrome.exe 为配套定制浏览器，runtime\v8trace-runtime.exe 为 C++ 内核。
  运行软件不需要 Node / Python；WinForms 界面使用 Windows .NET Framework。
  Python、CMake、Ninja、depot_tools、VS C++ x64、Windows SDK 仅为构建/测试条件。
  本轮实际使用 VS 2026、Windows SDK 10.0.26100.0、Jobs=1。
  本地 Windows 样本验收不代替 macOS、任意网站或算法复现验收。
  结果、哈希、回滚位置见《完整链路验收与交接-20261027.md》。
  本轮不执行签名、信任根导入、Git 提交/推送或远端发行。

二、定制 Chromium：独立编译命令
在 F:\project\chrome_envs 的 PowerShell 中执行：
  Set-Location F:\project\chrome_envs

固定版本：
  Chromium: 2903d8558c752b5a554a1a47b4ea7219ba1a31ef
  V8:       792d9716fea48312ad7ce4413c538e00628b1d50
  源码/缓存: G:\v8-trace-build\src
  输出:      G:\v8-trace-build\src\out\V8TraceProbe
  本轮证据:  artifacts/v8-trace-http-root-20261025/r7

当前 G 盘源码已受控接入本轮补丁，直接增量 Build，不重复 Sync / Configure：
  pwsh -NoProfile -File .\v8-trace\native\build-chromium.ps1 -Stage Build -Target chrome -BuildRoot G:\v8-trace-build -OutName V8TraceProbe -EvidencePath artifacts/v8-trace-http-root-20261025/r7 -Jobs 1 -Detailed -BrowserChannels
  if ($LASTEXITCODE -ne 0) { throw 'Chrome 构建失败；检查原始构建回执，此时不打包' }

成功后生成匹配的浏览器身份与运行文件清单：
  pwsh -NoProfile -File .\v8-trace\native\build-chromium.ps1 -Stage Package -Target chrome -BuildRoot G:\v8-trace-build -OutName V8TraceProbe -EvidencePath artifacts/v8-trace-http-root-20261025/r7 -Jobs 1 -Detailed -BrowserChannels
  if ($LASTEXITCODE -ne 0) { throw 'Chrome Package 失败' }

执行文件：
  G:\v8-trace-build\src\out\V8TraceProbe\chrome.exe
Package 在该目录生成 v8trace-opcode.json、v8trace-runtime-files.json。
不复制 obj / 缓存 / PDB；下面的软件打包会按清单附带 Chrome。

全新 checkout 或确实修改补丁时，单独选择新 EvidencePath，并先封存当前已应用补丁：
  $Evidence = 'artifacts/v8-trace-next-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
  pwsh -NoProfile -File .\v8-trace\native\build-chromium.ps1 -Stage Configure -BuildRoot G:\v8-trace-build -OutName V8TraceProbe -EvidencePath $Evidence -Jobs 1 -Detailed -BrowserChannels
已有补丁版本发生变更时还需显式 PreviousPatch，指向刚封存的旧 v8-opcode.patch。
随后 Build / Package 使用相同 $Evidence；不覆盖或跳过未知源码修改。Sync 下载依赖仅在确有需要时单独执行。
同一 checkout 只运行一个 Ninja，不改活动构建输入，不关闭用户应用来掩盖资源问题。
Build 自动使用目标的传递依赖图，保留优化与插桩；Jobs=1 不等于所有内存状态都必定成功。

d8 是独立辅助目标，不代替 Chrome 验收：
  pwsh -NoProfile -File .\v8-trace\native\build-chromium.ps1 -Stage Build -Target d8 -BuildRoot G:\v8-trace-build -OutName V8TraceProbe -EvidencePath artifacts/v8trace-d8-next-unique -Jobs 1 -Detailed -BrowserChannels
d8 的 EvidencePath 每次使用独立新路径，不覆盖 Chrome 回执；如先验证 d8，随后实际 Build chrome，再 Package。
本轮 R7 仅改 Base 私有实现，V8 公共输入未变，原 d8 已验证记录保留；没有用旧 d8 冒充新 Chrome 验收。

三、C++ 内核 + 可视化 EXE：独立编译命令
在 VS x64 开发者 PowerShell 中进入项目目录。输出目录必须全新，旧包保持不变。

仅编内核/界面，不附浏览器：
  $Out = '.\v8-trace\dist\V8Trace-Host-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff')
  pwsh -NoProfile -File .\v8-trace\build-cpp.ps1 -BuildRoot G:\v8-trace-build\runtime-mcp -OutputPath $Out -Jobs 1
  if ($LASTEXITCODE -ne 0) { throw 'C++ / UI 构建或测试失败' }

附带定制 Chromium 的完整软件：
  $Out = '.\v8-trace\dist\V8Trace-Full-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff')
  pwsh -NoProfile -File .\v8-trace\build-cpp.ps1 -BuildRoot G:\v8-trace-build\runtime-mcp -OutputPath $Out -NativeChromePath G:\v8-trace-build\src\out\V8TraceProbe\chrome.exe -Jobs 1
  if ($LASTEXITCODE -ne 0) { throw '软件与浏览器配套打包失败' }

入口会构建全部测试目标并运行 CTest，按 GN 清单附带 Chrome，初始化 LPAC 读取/执行权限。
本轮完整 CTest 为 29 项；编译/单测通过仍需新浏览器实际验收，新包保持候选身份。
MSVC+Ninja 的构建期 Python launcher 将探测到的 include 前缀规范为 ASCII、诊断转为 UTF-8，保持真实头文件依赖；不改变 C++ 语义，运行软件不依赖它。
UI 的 Chrome / 日志相对路径以 V8Trace.exe 所在目录为准；CLI 相对路径以启动它的工作目录为准。
Chrome 默认英文；不通过关闭浏览器沙箱处理启动故障。

四、实际无 CDP 样本验收
每轮使用全新证据目录。以下仅运行本地服务与独立 HTTP oracle：
  python -B .\v8-trace\runtime-cpp\tests\causality_browser_probe.py --runtime (Join-Path $Out 'runtime\v8trace-runtime.exe') --chrome (Join-Path $Out 'chromium\chrome.exe') --scenario finite --duration 45 --evidence ('G:\project\trace\finite-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))

分别将 scenario 设为 default-off / pending / unread，使用各自的新目录。
pending / unread 需要真实资源等待。unread 的两项 HTTP 未结束缺口及原 partial 必须保留。
暂停/手动停止、预算、异常退出命令见交接文档；后两项若尚无 HTTP 根落盘，就记录“无链证明”。
普通验收不附线程监视器，不设置诊断 flush 超时，不用浏览器自动化作复现兜底。
CLI capture/import 的状态、错误、最终摘要直接写文件；UI/Worker/MCP 的机器协议管道保留。
